# Parity with the Rust API

The reference surface is the public Rust processor (`src/api/processor.rs` and
its submodules) and builder (`src/api/builder.rs`, `src/api/mod.rs`) of the
bundled core, exposed through `api::portable`.

## Mappings

| Rust | C | Source of truth |
| --- | --- | --- |
| `TextForgeBuilderMethods::<method>` (77 methods) | `tf_pipeline_<method>` | Generated by `scripts/generate_builder.py`; listed in [builder-parity.json](builder-parity.json) |
| `define_replace_map(name, \|map\| map.add_replace(..).end())` | `tf_replace_map_builder_new` + `tf_replace_map_builder_add_replace` + `tf_pipeline_define_replace_map` | Hand-written, listed in builder-parity.json |
| `push_token`, `block_assoc`, `call_block`, `if_do_contains_each`, `build` | `tf_pipeline_push_token`, `tf_pipeline_block_assoc` (= `tf_pipeline_block`), `tf_pipeline_call_block`, `tf_pipeline_if_do_contains_each` (= `tf_pipeline_contains_each`), `tf_pipeline_build` | Hand-written |
| `TextForgeProcessor::<method>` (25 methods, incl. buffered and file I/O) | `tf_processor_<method>` | [processor-parity.json](processor-parity.json), checked by `scripts/check_parity.py` |
| Portable types (`PipelinePlan`, `CompiledPipeline`, `Observers`, `PortableBuffer`, `FilePath`, `BatchPool`, `BufferOptions`, `InstructionSpec`, `features`) | `tf_pipeline_*`, `tf_compiled_pipeline_*`, `tf_observers_*`, `tf_buffer_*`, `tf_file_path_*`, `tf_batch_pool_*`, `tf_buffer_options_new`, `tf_instruction_*`, `tf_features` | `scripts/check_parity.py` |

Adaptations follow C conventions without changing behavior: closures become
body pipelines and rule builders that are consumed; `Result` becomes
`TfStatus` + `TfError`; owned Rust strings become caller-owned `TfString`;
Rust traits for observers and streams become function pointers with
`user_data`; the builder's `?` chaining becomes the sticky error.

## Tests against the Rust implementation

* `tests/c/test_builder_parity.c` (generated) replays 84 cases — one or more
  per builder method plus variables, iteration, blocks, conditionals, replace
  maps and error cases — and compares output bytes or core error codes with
  `examples/builder_reference.rs`, which runs the public Rust builder.
* `tests/c/test_processor_parity.c` replays 30 processor cases (Unicode, NUL,
  missing IDs, snapshots, variables, regex, conversion/validation errors, text
  and bytecode persistence, buffers, watchers and their JSON report, callback
  errors, invalid UTF-8 streams and line-instruction errors) and compares stage,
  code, message, instruction and input with `examples/processor_reference.rs`.

Fixtures are tied to the bundled core revision; `--check` modes of the
generators fail in CI when the oracle output, the generated C test or the
mapping drifts.

## Known gaps

None. Rust trait objects and lifetimes have no C counterpart and are
represented by owned descriptions (`TfInstruction`) and opaque handles.
